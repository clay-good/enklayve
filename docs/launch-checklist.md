# Launch checklist

A single pass that confirms every acceptance criterion across **Phases 0–26** still holds — [SPEC](specs/SPEC.md) 0–11, [SPEC-2](specs/SPEC-2.md) 12–17, [SPEC-3](specs/SPEC-3.md)'s trust pass, and [SPEC-4](specs/SPEC-4.md)'s Pillar 4 (18–24) plus the two closing passes — along with the launch-specific gates (offline, audit, crawlability, clean deploy). Run it before announcing. Each box is either a command to run or a thing to verify; the commands are the same gate CI runs.

## The automated gate (must all be green)

```sh
npm run format:check
npm run lint
npm run typecheck
npm run test          # unit + golden corpus + axe accessibility
npm run build
npm run audit         # CSP, no cross-origin loads, provenance, no sensitive persistence
npm run deploy:dry
npm run test:e2e      # Playwright, its own CI job
```

Two more run on a schedule rather than per-commit, because they need the network and a flaky government site must not fail a build:

```sh
npm run check:links                        # every external link, monthly
npm run check:adapters                     # every refresh adapter still finds its figure, monthly
node scripts/refresh/watch-sources.ts      # the hand-authored Pillar 4 sources, quarterly
npm run check:boundaries                   # which inclusive/exclusive comparisons any test holds
npm run check:boundaries:classify          # and, for each survivor, whether a test COULD hold it
```

- [ ] `format:check`, `lint`, `typecheck` all clean.
- [ ] `test` green, including the tax-engine golden corpus, the bounds/fuzz invariants, and the axe sweep with **zero violations** — home, About, All Tools, Readout, Report, and **every calculator and hub, the roster derived from the registry** rather than a hand-kept list ([`catalogInvariants.test.ts`](../tests/ui/catalogInvariants.test.ts)).
- [ ] Every calculator **announces its answer**: its result sits inside an `aria-live` region, so a screen-reader user who types an income hears that the page replied. axe cannot catch this — it is an absence, not a violation — so the catalog sweep asserts it directly. Two mechanisms satisfy it (the `resultCard` headline `<output>`, and a tile's own `.tile-result` container); the sweep asserts the property rather than either one, since the eight Pillar 4 screeners have no single headline number and rely on the container alone.
- [ ] `check:boundaries` reports **no newly unheld comparison** against [`boundary-baseline.json`](../scripts/boundary-baseline.json). It flips every `<=`/`>=` in `src/engine` to its strict form and runs the suite: a comparison whose mutation still passes is a line no test holds. The statutes write these lines "at or below", so `<=` and `<` are different answers to a real person — and an exact threshold is measure-zero for an arbitrary input, so it only ever appears in a case somebody wrote on purpose. **47 of 68 were unheld on 2026-08-30**; **21 after three passes on 2026-08-31**. The first took nine, after [`statutoryThresholds.test.ts`](../tests/engine/statutoryThresholds.test.ts) put a household exactly on nine of them — the 100% FPL floor for the premium tax credit, SNAP's minimum benefit at a household of two, the open-ended top ACA band, Social Security's $25,000/$32,000/$34,000 provisional-income bases, the IRA phase-out endpoints, and the $290-a-week garnishment crossover where the two federal tests agree. Several of those compute the *same dollars* under either reading and differ only in the word beside the number — the tier, the status, which limit binds — which is exactly the class of error a suite of worked examples cannot see. The second took seven more — the thresholds the codebase set for itself (the $1 cliff-noise floor, the AMT screener's zero base and its 85% band, the swept range's top point) plus the January 15 / MLK collision that moves the fourth estimated-tax payment. The third took ten more across the goal plan and the finance engine, where the recurring hazard is that the plan's own advice is a dollar figure — so the person who follows it exactly is the person the flipped comparison fails. Every remaining entry now carries a **verdict, not just a line number**, and the verdict is now **computed rather than read**. `check:boundaries:classify` flips each survivor again and re-runs the engine over the values its comparisons test ([`observe-engine.ts`](../scripts/observe-engine.ts)) instead of the suite — 1.5 seconds a comparison instead of eight. A mutation that moves an observed value is a decision a test could hold; one that moves nothing is a branch whose `else` computes the same answer, which no test can ever hold. **All 21 survivors move nothing, and 0 are observable**: there is no known case left unwritten. That is evidence rather than proof, and what makes it worth believing is the **calibration** — all 47 *held* boundaries must be visible to the same probe, since a test distinguishes them by definition, and the report refuses to be trusted when one is not. It refused twice: eight held comparisons were invisible because the probe stood *near* their thresholds rather than on them, and one because a fixture used a shape `DeadlineDue` does not have and a cast let it compile. Both were the probe's fault, and both were found by the calibration rather than by a person. Re-run in full on **2026-09-01** — the first complete run under the crash-safe checker — and it reproduces the baseline exactly: 68 comparisons, 47 held, 21 unheld, 0 observable, no miscalibration, no newly unheld, and a clean `src/engine` at the end. The baseline holds the backlog so only a *new* one fails, and it is meant to shrink. Slow by construction (one suite run per comparison, ~25 minutes), so it runs on a schedule and on demand, never in the unit suite. It refuses to start if `src/engine` has uncommitted changes, because it rewrites files in place — and, since 2026-09-01, it **survives being killed**. The restore lived in a `finally`, which a signal does not run: Ctrl-C, or a CI job hitting its limit, left one flipped comparison on disk in a file nobody had edited. That state type-checks, builds, and shows a single test failure that reads like a regression somewhere unrelated — the exact class of silent wrong answer this check exists to hunt, planted by the hunter. It was found the way it would be found in practice: a fresh session ran the check, stopped it, and spent the next ten minutes looking at a goal-plan failure caused by a mutation abandoned in `socialSecurity.ts`. Two guards now, because one is not enough. The path being rewritten is **journalled** to `scripts/.boundary-mutation.json` before the rewrite and erased after the restore, so a later run puts back whatever a SIGKILL, an OOM or a closed lid left behind — recovery is `git checkout` on the one path the note names, which is safe precisely because the run refused to start unless that file was clean. And the suite is now spawned **asynchronously** rather than with `execFileSync`: a synchronous child blocks the event loop, so the handler that was supposed to interrupt the eight-minute run sat queued behind it, and the file stayed flipped for as long as anyone was watching. **The twenty-one survivors were read line by line on 2026-09-01 and every one now carries the reason no test holds it**, in the baseline itself, under the rule `watch-coverage.json` already applies to an unwatched dataset: a reason is a decision someone can argue with later, not a shrug. The classifier had said "no observed difference" for all twenty-one; what it could not say is *why*, and the three kinds are different work. **Seventeen are equivalent** — the `else` arm computes the same value at exactly that point, so asking for a test is asking for a fixture that manufactures a difference. **Three are unreachable**: `iraDeduction`'s guard against a zero it is never handed, `finance.ts:736`'s second clause that the first has already returned on, and a tie between the AOTC and the Lifetime Learning Credit that their own arithmetic keeps apart. **One is correct and unreachable**: `dueDates`' `date <= 21` really would misclassify Martin Luther King Jr. Day in 2030 and 2036, and no deadline this engine computes can land on January 21 to notice — holding it would mean exporting a helper for the test's benefit rather than a reader's. So the list should still shrink, but not by writing twenty-one tests; it shrinks when one of those functions gains a caller that can reach the line. A new entry now records with an **empty** reason, which the baseline's own test rejects until a person writes one, so recording costs a sentence. And a **`--file` run now speaks only about the file it checked**: it had been reporting every *other* file's baseline entries under "held now — remove them from it", which is an instruction to empty the baseline of twenty-one lines nothing had re-examined, after which the next full run would fail on all of them as newly unheld. Scoping narrows what a run may claim, not what it may catch — a boundary newly unheld inside the scope still fails it.

- [ ] The same catalog sweep is green on its other invariants: no tile throws or paints a non-finite value for a hostile *deep link* (a separate path from the form inputs the e2e drives), every enum param falls back to a value the reader can see, and every tile clears the bar — worked example, "how this works", "Learn more", deep-linkable state.
- [ ] `check:adapters` reports **no regressions against the committed baseline** ([`adapter-baseline.json`](../scripts/refresh/adapter-baseline.json)), which is the short list of adapters known to read their source correctly — **42 of 59 adapters watch their shard** as of 2026-08-30, up from 5. It does *not* gate on the raw unparsed count. That count is now **zero**: the other seventeen adapters are all `settled` refusals — a statutory figure that does not index, a state that has not published the shard's year, a page whose numbers mean something else. **Each of those seventeen is now written down** in the baseline's `unanchored` map, with one of two verdicts, and [`anchorCoverage.test.ts`](../tests/build/anchorCoverage.test.ts) fails until a new adapter has one. *WAITING ON THE SOURCE* is a date — eleven of them, where the state has not posted the shard's year and the adapter is right to refuse a closed document that would report agreement forever — and each says what would close it. Seven of those eleven close themselves, because the parser runs against the watched page first. The other four — Oregon, Nebraska, Arkansas, Vermont — are parked on a document at a **different URL**, so the page they watch will never state the figure and the entry has to say "repoint this adapter". Since 2026-09-01 each of those four carries an `awaiting` probe that watches for the day, and [`anchorCoverage.test.ts`](../tests/build/anchorCoverage.test.ts) fails if an entry tells a person to repoint and nothing watches for them. Each probe is **calibrated against the year that is published** and must see it: a pattern aimed at a URL a state can rename would otherwise report "still waiting" forever in the same words it uses when the wait is real, and that verdict is reported as `blind` and fails the check. An arrival fails it too — the shard is now knowably a year behind — and is not permission to scrape: repointing means dry-running the adapter and reading the diff, as always. The monthly job opens the issue on either verdict, and [`workflowOutputs.test.ts`](../tests/build/workflowOutputs.test.ts) fails when a scheduled check emits a count its workflow never names — the first version of the wait probes shipped writing `waitsOver` into a workflow that gated on two other counts, which is a check that does its work every month and tells nobody. *WILL NOT ANCHOR* is a decision — six, where there is no annual figure on the page or the page states a **different** figure that would be right by accident, like Connecticut's gross-income filing thresholds, which equal its personal exemption today and would diverge silently the first year the state moved one and not the other. Without the split, a healthy list of 42 reads as seventeen pieces of unwritten work, and a reader cannot tell Oregon — one URL, in a few months — from Delaware, whose deduction has not moved since 1999 and is fingerprinted for amendment instead. The BLS CPI adapter joined the watched list on 2026-08-30: its keyless API spends a daily quota against a shared runner IP, and since an unreachable adapter no longer counts as a regression even on the baseline, a source that answers most days can be watched without a monthly false alarm. A settled refusal is reported apart, writes no diff-log entry, and opens no pull request, because an issue listing the same non-events every month is the alert people learn to close unread. An adapter that cannot find its figure has stopped watching its shard, which then sits at whatever year it was authored in behind a citation that still looks live — the failure that left Illinois, Michigan, Missouri and Georgia stale until the August 2026 audit. The list should grow, and adding to it means dry-running the adapter and reading the diff, never watching the check go green. (Unreachable is reported separately and does not gate: usually the agency's afternoon, or a keyless API's daily quota. The check now splits off the unreachable that will **not** clear on its own — a server serving an incomplete certificate chain, which Node refuses every run forever, so the shard behind it has stopped being watched permanently rather than for a week. Mississippi was the standing case and is now repaired: the shared fetch follows the leaf's AIA pointer to the intermediate the server omits, verifies it against Node's root store, and retries with the chain complete — so no adapter is in that state today. It is still not gated, because it would fail every run by definition. Nor does an unreachable adapter that is *on* the baseline gate any more, which it used to: a single dropped connection under concurrency took a watched adapter out of the anchoring set and reported it under "Stopped anchoring", the one section that exits non-zero and files an issue. It is listed as not reached instead, and the fetch retries once.)
- [ ] `check:links` reports **0 broken and 0 redirected** (and, since it shares the refresh pipeline's certificate-chain repair, 0 unreachable). A redirect is not a pass: agencies reuse article ids, so an old link can land on a page that is authoritative and about something else. Three of the four findings on 2026-09-01 were the check's own: its URL pattern stopped at a `(`, so the eCFR's `section-1.401(a)(9)-9` was truncated to `section-1.401` and reported broken every month — a reader sent to repair a URL that works, while the URL actually shipped went unchecked; `example.invalid`, the reserved TLD the boundary probe uses for a source that must never resolve, was not on the fixture list; and an adapter's `awaiting` URL is *supposed* to 404, so those are excluded, derived from the adapters rather than listed. The fourth was real: Washington's `dor.wa.gov/taxes-rates/income-tax` 301s to `dor.wa.gov/income-tax`, the destination verified as the same page, and the shard now carries it.

A failure names the chunk that grew, so the fix is not simply raising the number — and a **pass now prints the figure and its headroom too**, because a gate that speaks only when it breaks means nobody learns how close it was until it does. As of 2026-09-01 the shell is **269.0 of 275 kB gzipped, 6.0 kB free** — the 69th calculator and its shard spent 2.8 of the 8.8 that dropping `/tools.html` bought back. As of 2026-09-01 the shell was **266.2 of 275 kB gzipped, 8.8 kB free** — after a day of correctness work took the headroom down to 4.0 kB and the argument the last paragraph of this entry had been deferring was finally had. **`/tools.html` left the precache** rather than the budget being raised a second time in one day: it is a crawl surface, the sixty-eight per-tile crawl shells beside it were never precached, and it cost 4.8 kB gzipped — a fifth of what was left — to make a page available offline that the in-app All Tools view already mirrors out of the shell that *is* precached. It is still built, still served, still in the sitemap, and runtime-cached the moment anyone opens it. The rule is a gate now (`checkPrecacheContents`), so the next static page cannot drift back in — the day's correctness work spent 4 kB of the 10.7 the raised budget bought, most of it in shard `sourceNote` prose, which is inlined into the entry chunk by `connect-src 'none'` like every other shard byte. A citation nobody can read is not a citation, so this is the intended trade; it is also the thing to measure first when the headroom next runs out — the budget was raised from 265 that day, deliberately and with the alternatives measured first, after a day of correctness work took the headroom from 2.0 kB to 0.7 kB: the SALT limitation moving from a constant to a cited shard field, IRC §170(p) being modeled, and both federal-tax tiles gaining a paragraph naming the three OBBBA deductions they still do not model. The reasoning lives beside the constant in [`audit-release.ts`](../scripts/audit-release.ts), because a raised number with no reason attached is how the last one drifted. The ten kilobytes buy about eleven of headroom rather than a fresh margin — the gate is still meant to trip. When that runs out, `npm run audit -- --breakdown` reads the entry chunk's own source map and ranks what is inside it, so the next person gets the map from a command rather than from a paragraph that has gone stale. Today it ranks `src/tiles` (all 69 calculators, eager), `src/engine`, **zod**, `src/ui`, **decimal.js**, `src/readout`, and the bundled shards. Almost none of it is trimmable by splitting: `connect-src 'none'` inlines the shards at build time, and the offline promise means a tile the reader has not visited still has to be precached, so moving tiles into lazy chunks shifts bytes between assets without reducing what a first visit costs. Each candidate was **measured on 2026-09-01**, so the next person can start from numbers rather than from this paragraph. The entry chunk is **94%** of the shell (248.1 kB gzipped of 263.6); everything else together — `index.html`, `tools.html`, the manifest and the two icons — is 6.6 kB, and the CSS 8.3. Inside the entry chunk the inlined shards are **78.6 kB gzipped**, and the breakdown now says what is inside *them* too, because the biggest single item in the shell turned out to be prose: **`sourceNote` text is 124.6 kB of the shards' 323 kB raw — 39% — and about 41.6 of their 78.6 kB gzipped, roughly 15% of the entire precached shell.** Nobody had that number before 2026-09-01 and this paragraph ranked trimming candidates without it. It is measured and not trimmed, and the reason is the integrity gate rather than sentiment: the loader recomputes each shard's sha256 over its **exact bytes** (§7.1), so the notes must be inside the bytes that are hashed — moving them to a lazily imported chunk would mean hashing something other than the file that is committed, and `connect-src 'none'` forbids fetching them later anyway. So the honest framing of the next budget raise is that it buys citations a reader can read offline. Minifying the committed JSON would save **2.8 kB** and cost the line-by-line diff readability of the files this project's whole claim rests on, which is a bad trade at that price. **zod** and **decimal.js** are the two large dependencies and both are load-bearing: `Money` is exact-decimal arithmetic over decimal.js, and the zod schemas are not decoration but the fail-safe itself — the SALT limitation is *required* on the federal shard precisely so a shard that cannot answer fails validation at load and raises the verify-before-relying banner. Removing runtime validation would remove that. So the honest position is that there is no cheap win left, and when the headroom runs out the choice is to raise the number deliberately or to drop something from the precache — `/tools.html` was 4.8 kB and a crawl surface the in-app All Tools view already mirrors, which made it the first thing to argue about — and on 2026-09-01 the argument was had and it left the precache. What remains after that is the honest position above: no cheap win, and the next raise buys citations a reader can read offline.

## Privacy & determinism (SPEC §2)

- [ ] No analytics, no third-party requests, no CDN fonts anywhere in the build.
- [ ] Sensitive inputs (income, balances) never persist and clear on unload; only theme/locale is in `localStorage`.
- [ ] Recomputing any tile from the same inputs + dataset version yields an identical result; deep links restore exact state.
- [ ] Every shipped figure resolves to a non-empty citation (the audit's provenance check).

## Offline & PWA (Phase 8)

- [ ] After a first visit, the site loads and computes with the network cut (the service worker serves the cached shell; lazily-loaded chunks like pdf.js, mammoth, and the OCR engine + its `/ocr/` wasm core and language model are runtime-cached on first use).
- [ ] A code or data change bumps the SW cache version (hashed from the asset list + `data/manifest.json`) so stale caches are dropped on activate.
- [ ] The app installs as a PWA with the royal-purple theme and a maskable icon.

## Accessibility (Phase 4, SPEC §11)

- [ ] axe-core: zero violations across all views, all 69 calculators, and all 12 hubs (in CI) — **and colour contrast (WCAG 1.4.3) in a real browser, in both themes** ([`contrast.spec.ts`](../e2e/contrast.spec.ts)). That rule is disabled in every unit-suite axe run because happy-dom has no computed colours, so the single most-failed criterion in the WCAG catalogue was the one nothing measured. It passes, and passed first time — the hand-verification against the theme tokens was right. The spec also asserts a floor on how many elements axe actually evaluated, because a bare `runOnly: ["color-contrast"]` is read by axe as a list of *tags* rather than rule ids and silently measures nothing; and it reports the handful of elements on gradient backgrounds that axe cannot judge either way, which is the boundary the hand check still owns.
- [ ] Full keyboard navigation; **visible focus, asserted in a real browser** ([`focusVisible.spec.ts`](../e2e/focusVisible.spec.ts)) — happy-dom has no computed styles and axe does not evaluate focus indicators at all, so this compares each control's appearance focused against unfocused across four views. Comparing appearance is the point: an earlier version asked whether the element or an ancestor *had* an outline or shadow, and passed everything, because the cards these controls sit in carry a shadow for elevation; modals are never traps (Close + Done + Escape + click-outside) and restore focus to the prior element on dismiss — and, since 2026-08-30, **Tab stays inside them**. `aria-modal="true"` tells assistive tech the rest of the page is not there and does nothing whatever to the Tab order, so the command palette used to hand focus to whatever sat behind its backdrop on one press: a control the reader cannot see, cannot click, and has no obvious way back from except guessing at Escape. A skip-to-content link (WCAG 2.4.1) is the first focusable element and focuses `<main>` directly; focus moves into the content region after each route change.
- [ ] Reduced-motion preference is respected (count-up and hover transitions).
- [ ] The single calm light theme is legible throughout (the dark and high-contrast themes and the toggle were retired 2026-06-01 for the simplest default); red used only for genuine warnings.
- [ ] The page scrolls vertically only on every device width **and orientation** (portrait widths 320–1440px and landscape phones are both measured in the e2e) — no horizontal drag on any tool (form controls shrink to their track, wide tables scroll within their own region, and an `overflow-x: clip` backstop guards the content column); the ⌘K palette stays within a short landscape viewport; `viewport-fit=cover` + safe-area insets keep the chrome clear of the notch.
- [ ] Printing any view (notably the Readout Report's Print action) drops the app chrome and interactive controls via `@media print` and lays the content out black-on-white without breaking tables across pages; the Report appendix prints each citation's URL (guarded by a print-media e2e).
