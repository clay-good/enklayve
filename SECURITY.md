# Security

enklayve computes every figure on your device. There is no server to attack, no account, and no data to leak: the Content-Security-Policy sets `connect-src 'none'`, so the page cannot open a network connection at all. That shapes what a vulnerability here looks like.

## Report a vulnerability

Use GitHub's private reporting: open the repository's [Security tab](https://github.com/clay-good/enklayve/security) and choose **Report a vulnerability**. It is enabled here, so the report stays private until there is a fix. Please do not open a public issue for a security problem.

Expect a first reply within a week.

## What counts

The promises in [README](README.md#the-privacy-guarantee-its-literal) are the threat model. A report is in scope if it breaks one of them:

- **Data leaving the device.** Any path that sends an input anywhere — a request the CSP does not block, a redirect carrying a value, a figure in a URL that gets sent to a third party.
- **Sensitive input persisting.** Income, balances and similar figures live in memory and clear on unload. Only the theme and locale preference may touch `localStorage`.
- **A weakened header.** The Worker sets the CSP, HSTS, `Referrer-Policy: no-referrer`, frame and permissions policies. A response missing one, or serving a looser CSP, is a vulnerability rather than a bug.
- **The encrypted ledger.** A saved ledger file is encrypted with a passphrase. Anything that weakens that — a key-derivation mistake, a plaintext leak, a file that decrypts without the passphrase — is in scope.
- **Supply chain.** A dependency or build step that could inject code into what ships.

**A wrong number is not a security issue** — it is the most useful bug report this project can get, and it belongs in a public issue where it can be cited and argued with. Open one with the source that proves it.

## Out of scope

Missing headers on a domain this project does not serve, reports generated by a scanner with no working proof, denial of service against a static site, and anything requiring physical access to an unlocked device.
