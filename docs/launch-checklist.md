# Launch checklist

A single pass that confirms every acceptance criterion across **Phases 0–26** still holds — [SPEC](specs/SPEC.md) 0–11, [SPEC-2](specs/SPEC-2.md) 12–17, [SPEC-3](specs/SPEC-3.md)'s trust pass, and [SPEC-4](specs/SPEC-4.md)'s Pillar 4 (18–24) plus the two closing passes — along with the launch-specific gates (offline, audit, crawlability, clean deploy). Run it before announcing. Each box is either a command to run or a thing to verify; the commands are the same gate CI runs.

## The automated gate (must all be green)

```sh
npm run format:check
npm run lint
npm run typecheck
npm run test          # unit + golden corpus + axe accessibility
npm run build
npm run audit         # CSP, no cross-origin loads, provenance, no sensitive persistence
npm run deploy:dry
npm run test:e2e      # Playwright, its own CI job
```

Two more run on a schedule rather than per-commit, because they need the network and a flaky government site must not fail a build:

```sh
npm run check:links                        # every external link, monthly
npm run check:adapters                     # every refresh adapter still finds its figure, monthly
node scripts/refresh/watch-sources.ts      # the hand-authored Pillar 4 sources, quarterly
npm run check:boundaries                   # which inclusive/exclusive comparisons any test holds
npm run check:boundaries:classify          # and, for each survivor, whether a test COULD hold it
```

- [ ] `format:check`, `lint`, `typecheck` all clean.
- [ ] `test` green, including the tax-engine golden corpus, the bounds/fuzz invariants, and the axe sweep with **zero violations** — home, About, All Tools, Readout, Report, and **every calculator and hub, the roster derived from the registry** rather than a hand-kept list ([`catalogInvariants.test.ts`](../tests/ui/catalogInvariants.test.ts)).
- [ ] Every calculator **announces its answer**: its result sits inside an `aria-live` region, so a screen-reader user who types an income hears that the page replied. axe cannot catch this — it is an absence, not a violation — so the catalog sweep asserts it directly. Two mechanisms satisfy it (the `resultCard` headline `<output>`, and a tile's own `.tile-result` container); the sweep asserts the property rather than either one, since the eight Pillar 4 screeners have no single headline number and rely on the container alone.
- [ ] `check:boundaries` reports **no newly unheld comparison** against [`boundary-baseline.json`](../scripts/boundary-baseline.json). It flips every `<=`/`>=` in `src/engine` to its strict form and runs the suite: a comparison whose mutation still passes is a line no test holds. The statutes write these lines "at or below", so `<=` and `<` are different answers to a real person — and an exact threshold is measure-zero for an arbitrary input, so it only ever appears in a case somebody wrote on purpose. **47 of 68 were unheld on 2026-08-30**; **21 after three passes on 2026-08-31**. The first took nine, after [`statutoryThresholds.test.ts`](../tests/engine/statutoryThresholds.test.ts) put a household exactly on nine of them — the 100% FPL floor for the premium tax credit, SNAP's minimum benefit at a household of two, the open-ended top ACA band, Social Security's $25,000/$32,000/$34,000 provisional-income bases, the IRA phase-out endpoints, and the $290-a-week garnishment crossover where the two federal tests agree. Several of those compute the *same dollars* under either reading and differ only in the word beside the number — the tier, the status, which limit binds — which is exactly the class of error a suite of worked examples cannot see. The second took seven more — the thresholds the codebase set for itself (the $1 cliff-noise floor, the AMT screener's zero base and its 85% band, the swept range's top point) plus the January 15 / MLK collision that moves the fourth estimated-tax payment. The third took ten more across the goal plan and the finance engine, where the recurring hazard is that the plan's own advice is a dollar figure — so the person who follows it exactly is the person the flipped comparison fails. Every remaining entry now carries a **verdict, not just a line number**, and the verdict is now **computed rather than read**. `check:boundaries:classify` flips each survivor again and re-runs the engine over the values its comparisons test ([`observe-engine.ts`](../scripts/observe-engine.ts)) instead of the suite — 1.5 seconds a comparison instead of eight. A mutation that moves an observed value is a decision a test could hold; one that moves nothing is a branch whose `else` computes the same answer, which no test can ever hold. **All 21 survivors move nothing, and 0 are observable**: there is no known case left unwritten. That is evidence rather than proof, and what makes it worth believing is the **calibration** — all 47 *held* boundaries must be visible to the same probe, since a test distinguishes them by definition, and the report refuses to be trusted when one is not. It refused twice: eight held comparisons were invisible because the probe stood *near* their thresholds rather than on them, and one because a fixture used a shape `DeadlineDue` does not have and a cast let it compile. Both were the probe's fault, and both were found by the calibration rather than by a person. Re-run in full on **2026-09-01** — the first complete run under the crash-safe checker — and it reproduces the baseline exactly: 68 comparisons, 47 held, 21 unheld, 0 observable, no miscalibration, no newly unheld, and a clean `src/engine` at the end. The baseline holds the backlog so only a *new* one fails, and it is meant to shrink. Slow by construction (one suite run per comparison, ~25 minutes), so it runs on a schedule and on demand, never in the unit suite. It refuses to start if `src/engine` has uncommitted changes, because it rewrites files in place — and, since 2026-09-01, it **survives being killed**. The restore lived in a `finally`, which a signal does not run: Ctrl-C, or a CI job hitting its limit, left one flipped comparison on disk in a file nobody had edited. That state type-checks, builds, and shows a single test failure that reads like a regression somewhere unrelated — the exact class of silent wrong answer this check exists to hunt, planted by the hunter. It was found the way it would be found in practice: a fresh session ran the check, stopped it, and spent the next ten minutes looking at a goal-plan failure caused by a mutation abandoned in `socialSecurity.ts`. Two guards now, because one is not enough. The path being rewritten is **journalled** to `scripts/.boundary-mutation.json` before the rewrite and erased after the restore, so a later run puts back whatever a SIGKILL, an OOM or a closed lid left behind — recovery is `git checkout` on the one path the note names, which is safe precisely because the run refused to start unless that file was clean. And the suite is now spawned **asynchronously** rather than with `execFileSync`: a synchronous child blocks the event loop, so the handler that was supposed to interrupt the eight-minute run sat queued behind it, and the file stayed flipped for as long as anyone was watching.

- [ ] The same catalog sweep is green on its other invariants: no tile throws or paints a non-finite value for a hostile *deep link* (a separate path from the form inputs the e2e drives), every enum param falls back to a value the reader can see, and every tile clears the bar — worked example, "how this works", "Learn more", deep-linkable state.
- [ ] `check:adapters` reports **no regressions against the committed baseline** ([`adapter-baseline.json`](../scripts/refresh/adapter-baseline.json)), which is the short list of adapters known to read their source correctly — **42 of 59 adapters watch their shard** as of 2026-08-30, up from 5. It does *not* gate on the raw unparsed count. That count is now **zero**: the other seventeen adapters are all `settled` refusals — a statutory figure that does not index, a state that has not published the shard's year, a page whose numbers mean something else. **Each of those seventeen is now written down** in the baseline's `unanchored` map, with one of two verdicts, and [`anchorCoverage.test.ts`](../tests/build/anchorCoverage.test.ts) fails until a new adapter has one. *WAITING ON THE SOURCE* is a date — eleven of them, where the state has not posted the shard's year and the adapter is right to refuse a closed document that would report agreement forever — and each says what would close it. Seven of those eleven close themselves, because the parser runs against the watched page first. The other four — Oregon, Nebraska, Arkansas, Vermont — are parked on a document at a **different URL**, so the page they watch will never state the figure and the entry has to say "repoint this adapter". Since 2026-09-01 each of those four carries an `awaiting` probe that watches for the day, and [`anchorCoverage.test.ts`](../tests/build/anchorCoverage.test.ts) fails if an entry tells a person to repoint and nothing watches for them. Each probe is **calibrated against the year that is published** and must see it: a pattern aimed at a URL a state can rename would otherwise report "still waiting" forever in the same words it uses when the wait is real, and that verdict is reported as `blind` and fails the check. An arrival fails it too — the shard is now knowably a year behind — and is not permission to scrape: repointing means dry-running the adapter and reading the diff, as always. The monthly job opens the issue on either verdict, and [`workflowOutputs.test.ts`](../tests/build/workflowOutputs.test.ts) fails when a scheduled check emits a count its workflow never names — the first version of the wait probes shipped writing `waitsOver` into a workflow that gated on two other counts, which is a check that does its work every month and tells nobody. *WILL NOT ANCHOR* is a decision — six, where there is no annual figure on the page or the page states a **different** figure that would be right by accident, like Connecticut's gross-income filing thresholds, which equal its personal exemption today and would diverge silently the first year the state moved one and not the other. Without the split, a healthy list of 42 reads as seventeen pieces of unwritten work, and a reader cannot tell Oregon — one URL, in a few months — from Delaware, whose deduction has not moved since 1999 and is fingerprinted for amendment instead. The BLS CPI adapter joined the watched list on 2026-08-30: its keyless API spends a daily quota against a shared runner IP, and since an unreachable adapter no longer counts as a regression even on the baseline, a source that answers most days can be watched without a monthly false alarm. A settled refusal is reported apart, writes no diff-log entry, and opens no pull request, because an issue listing the same non-events every month is the alert people learn to close unread. An adapter that cannot find its figure has stopped watching its shard, which then sits at whatever year it was authored in behind a citation that still looks live — the failure that left Illinois, Michigan, Missouri and Georgia stale until the August 2026 audit. The list should grow, and adding to it means dry-running the adapter and reading the diff, never watching the check go green. (Unreachable is reported separately and does not gate: usually the agency's afternoon, or a keyless API's daily quota. The check now splits off the unreachable that will **not** clear on its own — a server serving an incomplete certificate chain, which Node refuses every run forever, so the shard behind it has stopped being watched permanently rather than for a week. Mississippi was the standing case and is now repaired: the shared fetch follows the leaf's AIA pointer to the intermediate the server omits, verifies it against Node's root store, and retries with the chain complete — so no adapter is in that state today. It is still not gated, because it would fail every run by definition. Nor does an unreachable adapter that is *on* the baseline gate any more, which it used to: a single dropped connection under concurrency took a watched adapter out of the anchoring set and reported it under "Stopped anchoring", the one section that exits non-zero and files an issue. It is listed as not reached instead, and the fetch retries once.)
- [ ] `check:links` reports **0 broken and 0 redirected** (and, since it shares the refresh pipeline's certificate-chain repair, 0 unreachable). A redirect is not a pass: agencies reuse article ids, so an old link can land on a page that is authoritative and about something else. Three of the four findings on 2026-09-01 were the check's own: its URL pattern stopped at a `(`, so the eCFR's `section-1.401(a)(9)-9` was truncated to `section-1.401` and reported broken every month — a reader sent to repair a URL that works, while the URL actually shipped went unchecked; `example.invalid`, the reserved TLD the boundary probe uses for a source that must never resolve, was not on the fixture list; and an adapter's `awaiting` URL is *supposed* to 404, so those are excluded, derived from the adapters rather than listed. The fourth was real: Washington's `dor.wa.gov/taxes-rates/income-tax` 301s to `dor.wa.gov/income-tax`, the destination verified as the same page, and the shard now carries it.
- [ ] `build` produces `dist/`; `deploy:dry` succeeds.
- [ ] `audit` passes: `connect-src 'none'` on pages, no cross-origin loads in `index.html`, every dataset shard cited, `localStorage` touched only by the theme/locale boundary, and the **precached shell inside its gzipped budget** — the bytes a first visit costs and offline requires. A failure names the chunk that grew, so the fix is not simply raising the number — and a **pass now prints the figure and its headroom too**, because a gate that speaks only when it breaks means nobody learns how close it was until it does. As of 2026-09-01 the shell is **266.6 of 275 kB gzipped, 8.4 kB free** — the budget was raised from 265 that day, deliberately and with the alternatives measured first, after a day of correctness work took the headroom from 2.0 kB to 0.7 kB: the SALT limitation moving from a constant to a cited shard field, IRC §170(p) being modeled, and both federal-tax tiles gaining a paragraph naming the three OBBBA deductions they still do not model. The reasoning lives beside the constant in [`audit-release.ts`](../scripts/audit-release.ts), because a raised number with no reason attached is how the last one drifted. The ten kilobytes buy about eleven of headroom rather than a fresh margin — the gate is still meant to trip. When that runs out, `npm run audit -- --breakdown` reads the entry chunk's own source map and ranks what is inside it, so the next person gets the map from a command rather than from a paragraph that has gone stale. Today it ranks `src/tiles` (all 68 calculators, eager), `src/engine`, **zod**, `src/ui`, **decimal.js**, `src/readout`, and the bundled shards. Almost none of it is trimmable by splitting: `connect-src 'none'` inlines the shards at build time, and the offline promise means a tile the reader has not visited still has to be precached, so moving tiles into lazy chunks shifts bytes between assets without reducing what a first visit costs. Each candidate was **measured on 2026-09-01**, so the next person can start from numbers rather than from this paragraph. The entry chunk is **94%** of the shell (248.1 kB gzipped of 263.6); everything else together — `index.html`, `tools.html`, the manifest and the two icons — is 6.6 kB, and the CSS 8.3. Inside the entry chunk the inlined shards are **75.9 kB gzipped**; minifying the committed JSON would save **2.8 kB** and cost the line-by-line diff readability of the files this project's whole claim rests on, which is a bad trade at that price. **zod** and **decimal.js** are the two large dependencies and both are load-bearing: `Money` is exact-decimal arithmetic over decimal.js, and the zod schemas are not decoration but the fail-safe itself — the SALT limitation is *required* on the federal shard precisely so a shard that cannot answer fails validation at load and raises the verify-before-relying banner. Removing runtime validation would remove that. So the honest position is that there is no cheap win left, and when the headroom runs out the choice is to raise the number deliberately or to drop something from the precache — `/tools.html` is 4.8 kB and is a crawl surface the in-app All Tools view already mirrors, which makes it the first thing to argue about.

## Accessibility (Phase 4, SPEC §11)

- [ ] axe-core: zero violations across all views, all 68 calculators, and all 12 hubs (in CI) — **and colour contrast (WCAG 1.4.3) in a real browser, in both themes** ([`contrast.spec.ts`](../e2e/contrast.spec.ts)). That rule is disabled in every unit-suite axe run because happy-dom has no computed colours, so the single most-failed criterion in the WCAG catalogue was the one nothing measured. It passes, and passed first time — the hand-verification against the theme tokens was right. The spec also asserts a floor on how many elements axe actually evaluated, because a bare `runOnly: ["color-contrast"]` is read by axe as a list of *tags* rather than rule ids and silently measures nothing; and it reports the handful of elements on gradient backgrounds that axe cannot judge either way, which is the boundary the hand check still owns.
- [ ] Full keyboard navigation; **visible focus, asserted in a real browser** ([`focusVisible.spec.ts`](../e2e/focusVisible.spec.ts)) — happy-dom has no computed styles and axe does not evaluate focus indicators at all, so this compares each control's appearance focused against unfocused across four views. Comparing appearance is the point: an earlier version asked whether the element or an ancestor *had* an outline or shadow, and passed everything, because the cards these controls sit in carry a shadow for elevation; modals are never traps (Close + Done + Escape + click-outside) and restore focus to the prior element on dismiss — and, since 2026-08-30, **Tab stays inside them**. `aria-modal="true"` tells assistive tech the rest of the page is not there and does nothing whatever to the Tab order, so the command palette used to hand focus to whatever sat behind its backdrop on one press: a control the reader cannot see, cannot click, and has no obvious way back from except guessing at Escape. A skip-to-content link (WCAG 2.4.1) is the first focusable element and focuses `<main>` directly; focus moves into the content region after each route change.
- [ ] Reduced-motion preference is respected (count-up and hover transitions).
- [ ] The single calm light theme is legible throughout (the dark and high-contrast themes and the toggle were retired 2026-06-01 for the simplest default); red used only for genuine warnings.
- [ ] The page scrolls vertically only on every device width **and orientation** (portrait widths 320–1440px and landscape phones are both measured in the e2e) — no horizontal drag on any tool (form controls shrink to their track, wide tables scroll within their own region, and an `overflow-x: clip` backstop guards the content column); the ⌘K palette stays within a short landscape viewport; `viewport-fit=cover` + safe-area insets keep the chrome clear of the notch.
- [ ] Printing any view (notably the Readout Report's Print action) drops the app chrome and interactive controls via `@media print` and lays the content out black-on-white without breaking tables across pages; the Report appendix prints each citation's URL (guarded by a print-media e2e).

## Content & correctness

- [ ] **The federal-taxable-income states inherit the federal deductions, and each one was asked separately.** Verified on 2026-09-01 against each state's own law. Four states start their income tax at *federal taxable income*, which is AGI minus everything §63(b) subtracts — including all five of the One Big Beautiful Bill Act's new deductions. So a tipped worker in North Dakota gets §224 on the state return too, without North Dakota legislating anything, and an engine that starts every state at AGI charges them state tax on income the state does not tax. A Montana single filer earning $60,000 with $8,000 of tips was being shown **$376.00 of Montana tax they do not owe**, which is now a golden case. **Colorado** (C.R.S. §39-22-104, and the Department of Revenue's Individual Income Tax Guide, "Colorado income tax is based generally on federal taxable income") adds back the overtime deduction for 2026 and later under HB25-1296 and says in the *next sentence* that "no addback is required ... for qualified tips" — so the shard block is five booleans, not one, and a state that carries it must answer for each deduction. **Idaho** (Idaho Code §63-3004) conforms *statically* to the IRC "as amended and in effect on the first day of January 2026", carving out only §85 and the research-expenditure treatment in §70302 of Pub. L. 119-21, so all five flow through — but the answer there changes by bill, not by calendar. **Montana** (MCA §15-30-2120(1)) adds back only §199A and the §164(a)(3) state income tax deduction. **North Dakota** (N.D.C.C. §57-38-30.3(2)) conforms *rolling* — "as computed under the Internal Revenue Code of 1986, as amended" — with nine adjustments that touch none of this. **New Mexico is the case that makes the block's absence mean something**: it uses the federal standard deduction figures and looks like conformity, but NMSA §7-2-2 starts it at adjusted gross income and subtracts "an amount equal to the standard deduction allowed ... by Section 63", which is §63(c) alone — nothing in §63(b) reaches it, and a test asserts it stays unchanged. **Iowa and Oregon are named by the Tax Foundation as federal-taxable-income states and are deliberately not answered here**: this engine models Oregon with its own $2,835 standard deduction and Iowa with a conformed standard deduction, so each needs its own pass against its own form before a conformity block is written for it. An unanswered question written down is a decision; an unanswered question nobody recorded is the state tax being wrong.
- [ ] Federal/state/FICA golden cases cross-checked against published worked examples for the seeded tax year. The corpus checks the engine against itself, which is exactly the class of error it cannot see: on 2026-09-01 the engine's `SALT_CAP = 10000` turned out to predate the One Big Beautiful Bill Act's rewrite of IRC §164(b)(6)-(7) ($40,400 for 2026, phasing down by 30% of MAGI over $505,000 to a $10,000 floor, halved for a separate return), and a golden case was pinning the wrong answer — $2,400 of federal tax a single filer with $20,000 of state and local tax does not owe. It is now a **field on the federal shard**, required there by the schema so a shard that cannot answer fails validation instead of being answered for, cited to the Code, and watched at 26 U.S.C. §164 so the 1%-a-year steps through 2029 reach a person. The lesson generalises: a constant is invisible to every gate here — the provenance audit, the adapters, the staleness banner, the source watch all see datasets. That is now a test rather than a lesson: [`numericConstants.test.ts`](../tests/build/numericConstants.test.ts) lists every named numeric constant in `src/engine`, `src/readout`, `src/profile`, `src/tiles` and `src/ui`, and fails until each carries a verdict — a **bound** the code owns (a loop ceiling, a probe size, a unit conversion), a **figure** somebody legislates, or an **assumption** this site chose. Forty-eight today. The three figures are the 7.5% medical-expense floor (IRC §213(a), permanent since the Consolidated Appropriations Act 2021), the $150,000 AGI above which the estimated-tax safe harbor rises to 110% (§6654(d)(1)(C)(i), unmoved since 1993), and the five-year Roth conversion seasoning period (§408A(d)(3)(F)) — each a period or an unindexed threshold rather than an annual amount, left in code deliberately with the decision written where the next reader can argue with it. Naming **assumption** as a third verdict is what stops a modelling choice — a 4% savings rate, the 28/36 lending convention — being filed as a bound, which is where they hide. The sweep started at the engine and was widened the moment it was pointed one directory over: `src/readout` held `FALLBACK_LIMIT = 24500`. The last statutory number in the codebase, §1211(b)'s $3,000 capital-loss offset, was an inline `fields.mfs ? 1500 : 3000` in the middle of a handler — the one shape a named-constant sweep cannot find — and is now named, verdicted, and bound to the sentence that quotes it. Every statutory figure this site holds is either a shard field or a constant with a written reason. Named constants only — an inline literal is a harder sweep — but that is the shape the three hardening passes kept finding.
- [ ] Every tile has a worked example, a "How this works" explainer, "Learn more" links, and the on-device / US-only / not-advice promise. **The dollar figures in those explainers are read back out of the shards** ([`proseFigures.test.ts`](../tests/ui/proseFigures.test.ts)): 29 bindings across nine tiles, plus a completeness half that fails on any dollar figure in those files that is neither bound nor written down as not-a-figure. Prose goes stale the way a constant does, and worse — the number the reader is told and the number the calculator uses end up on the same screen disagreeing, and nothing compares a sentence to a shard. Two were live on 2026-09-01, both from the One Big Beautiful Bill Act: the federal-tax explainer said SALT was "capped at $10,000" after the engine was fixed to $40,400, and the **Child Tax Credit explainer said "$2,000 per qualifying child" while the shard had carried $2,200 since the Act** — so that tile computed $2,200 under a paragraph saying $2,000. The gift-tax figures matter most here, since all three index annually.
- [ ] **All five of the One Big Beautiful Bill Act's new deductions are modeled, each on the tile that has the input it needs.** Verified against the Code on 2026-09-01: the $6,000-per-person deduction at 65 (IRC §151(d)(5)(C), taxable years before 2029), up to $25,000 of qualified tips (§224), up to $12,500 of qualified overtime — $25,000 on a joint return — (§225), each reduced by $100 per $1,000 of MAGI over $150,000/$300,000, and $1,000 of charitable giving without itemizing, $2,000 jointly (§170(p)). **§170(p) is modeled as of 2026-09-01** — it is the one that needs no new input, because both tiles have asked for charitable giving since launch as part of the itemized "big four". §63(b)(4) subtracts it from AGI *alongside* the standard deduction rather than as part of it, so it is reported on its own line and kept out of the deduction figure Utah's taxpayer credit is a share of; and the auto standard-vs-itemized choice now compares the itemized total against standard **plus** §170(p), since itemizing forfeits it. The engine's `charitable` input does not separate cash from property or a public charity from a donor-advised fund, and §170(p) counts only the first of each, so the tile says the real figure may be smaller. **§151(d)(5)(C) followed the same day**, once the input question was asked properly: the statute needs a *count* of people aged 65 on the return, not an age, so both tiles ask "how many of you are 65 or older" — a three-option select, which is a smaller thing to ask a reader for than a birth date and is exactly what the rule consumes. $6,000 each, reduced by 6% of MAGI over $75,000 or $150,000 joint, so it runs out at $175,000 and $250,000. Three readings that a reasonable implementation gets wrong each have a case: married filing separately gets **zero, not half** (§151(d)(5)(C)(v)); the phase-out reduces the **per-person** amount, so a couple lose twelve cents per dollar rather than six; and a qualifying surviving spouse files at joint rates without filing a joint return, so they get one individual at the single threshold. Unlike §170(p) it applies **whether or not the filer itemizes** (§63(a) for an itemizer, §63(b)(2) for one who is not), which is its own case too. **§224 and §225 followed**, on Take-Home, which is the tile a server or an hourly worker actually opens and the one where wage composition belongs: two fields asking how much of the pay was qualified tips or an overtime premium. One engine function serves both, because the statutes are one shape — but the **phase-down is a step where the Act's other two are rates**, and it is not the child credit's step either: "$100 for each $1,000 by which ... exceeds" counts *completed* thousands, because neither section says "or fraction thereof" and §24(b)(2) does. A filer $1,999 over the threshold loses $100, not $200. Three phase-outs, three shapes, one Act. §224 has **no joint figure at all** where §225 doubles to $25,000, which is the other way these two look alike and are not. Both are income-tax deductions only — FICA is still owed on every tipped and overtime dollar, which the explainer says and a test asserts — and what qualifies is narrower than the words suggest (cash tips in a Treasury-listed occupation; the premium half of FLSA-required overtime), so the tile calls the figure a ceiling. Neither tile claims a deduction it has no input for: Take-Home has no giving field, the Federal Income Tax tile has no wage breakdown, and each says which tool applies the other. They were found while chasing the SALT constant and were nowhere: not in the engine, not on the deferred list, not on the page. An omission written down is a decision; an omission nobody recorded is a wrong number with nothing attached to it. Both tiles' explainers now name all four and say plainly that a reader they apply to owes less than the figure shown. **§163(h)(4) — car loan interest — was the fifth, and it was missing from the list of four**: the Act's §70203 takes qualified passenger vehicle loan interest out of the personal interest §163(h)(1) disallows, and §63(b)(7) reaches it for a filer who does not itemize, so up to **$10,000** a year comes off either way. It lives on the Federal Income Tax tile, beside mortgage interest but outside the itemized group, because the choice does not affect it. Two readings that "it is the same shape as tips and overtime" gets wrong, each with a case: (C)(ii) says "$200 for each $1,000 **(or portion thereof)**", so a filer one dollar into a thousand loses the whole $200 where a tipped worker in the same position loses nothing — a **fourth phase-out shape** in one Act — and the section carries **no joint-return restriction**, so a married individual filing separately is eligible at the $100,000 threshold where §224(f) and §225(e) would give them zero. Both are now **fields on the shard** (`partialStepCounts`, `jointReturnOnly`) rather than a convention the engine applies to every rule of that shape, so the next same-shaped section has to state its answer. The Auto Loan tile, which computes the interest figure the deduction is measured on, names the rule and points at the tool that applies it — and its three quoted figures joined [`proseFigures.test.ts`](../tests/ui/proseFigures.test.ts) rather than being trusted, because a second file quoting a shard is a second place for it to go stale.
